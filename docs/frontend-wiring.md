# Frontend operation wiring

This map connects frontend control groups to their backend operations and executable checks. Constructed paths and retained commands are listed with the widgets that consume them.

Business calculations, validation, authorization, revisions and persistence remain backend responsibilities. Display controls can correctly operate entirely in the browser. A field is considered connected when its selected value reaches the operation that consumes it; merely finding a matching route was insufficient.

## Interaction contracts

| Trigger | Required behavior | Regression evidence |
| --- | --- | --- |
| Change Dashboard Positions books, preset or definition while price units are loading | Earlier directory/catalog replies and errors cannot populate the new selection; entered sizes reach the exact saved definition. | [Positions controls](../web/tests/dashboard-position-controls.test.mjs) |
| Change PPA pending-actuals policy, native month, binding or side while a read is pending | The previous result cannot repaint under the new selector. | [PPA controls](../web/tests/ppa-editor-browser.test.mjs) |
| Change the selected PPA book | Directory pagination resets and old page actions cannot remain active for the new book. | [PPA controls](../web/tests/ppa-editor-browser.test.mjs) |
| Change the UTC offset of a reviewed repeated-hour PPA termination | The boundary review and confirmation are invalidated before submission. | [PPA controls](../web/tests/ppa-editor-browser.test.mjs) |
| Page the automation Jobs table while collection jobs show another page | Each pager preserves the other table's request coordinates. | [Jobs](../tests/browser/jobs.mjs) |
| Import explicit dates, then run another action | Monthly generator fields remain disabled while imported dates drive the backend definition; busy synchronization cannot re-enable ignored inputs. | [Contract dates](../tests/browser/contract-dates.mjs) |
| Navigate to Hourly prices or Power TOUs with an unapplied historical selection | The shared selection is applied first. These current-definition readers then give the backend's explicit historical refusal instead of reading the previous working context. | [Interval curves](../tests/browser/interval-curves.mjs), [Power](../tests/browser/power.mjs) |
| Change account or remount a gas ticket while a command is pending | Retention belongs to the captured actor, product and, for daily entries, trade. An abandoned reply cannot navigate the new view, strand status/retry controls, or clear/overwrite a newer same-actor request. Original requests remain available for active reconciliation. | [Ticket identity and recovery](../web/tests/ticket-identity-browser.test.mjs) |
| Open a physical gas trade in the read-only trade window | Daily quantity write controls are unavailable even when the account may record quantities elsewhere; the window retains its explicit read-only request boundary. | [Ticket identity and recovery](../web/tests/ticket-identity-browser.test.mjs), [Trade windows](../tests/browser/position-popout.mjs) |
| Run the verification entry point with an explicit browser | Frontend browser-control checks receive that executable through `CHROME_BIN`, including on Linux CI. | [Verification runner](../tests/test_check_all.py) |

Amendment editors keep Preview changes, explicit confirmation and Save amendment visible together. Pricing refusals appear locally, and Details can maximize/restore without discarding edits. See [Blotter workbench](blotter-workbench.md#details-pane).

## Verification

Run the complete verification entry point with the browser and database binaries described in [verification](verification.md). Its explicit browser selection is forwarded to frontend control checks through `CHROME_BIN`.

- [Frontend checks](../web/tests) cover control state, payload construction, delayed responses, read-only behavior and retained-request recovery. Focused browser fixtures use controlled synthetic API responses to force response ordering.
- [Owned browser scenarios](../tests/browser) exercise the actual application against newly created disposable databases. They cover pricing, booking, amendments, physical quantities, settlement, saved configuration and permissions.
- [Verification runner checks](../tests/test_check_all.py) verify that the selected browser reaches frontend checks on supported platforms.

The control map identifies applicable checks. It is not a claim that every possible input or external installation is qualified.

## Capability boundaries

- Sort/filter presentation, column visibility, chart zoom/drawings, graph/pane layout and temporary maximize state intentionally do not create financial backend writes. Saved account dashboard/table layouts use their own persistence operations.
- Unsupported capabilities remain explicitly unavailable. The map does not imply support for coming-soon product kinds, unsupported physical settlement/risk profiles, or historical readers that the backend refuses.
- Assistant integration checks use a controlled HTTP provider. Infrastructure checks cover authorized configuration, queued commands and synthetic observations; external provider accounts and actual container deployments require their own qualification.
